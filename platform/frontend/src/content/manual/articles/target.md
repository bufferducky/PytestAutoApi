# 目标系统：到底测哪个服务

目标把服务地址、登录协议、环境和上下文要求组合起来。

## 先保存目标，再选择身份 {#order}

在环境管理顶部选择“目标系统”标签页，新增并保存；身份和项目绑定引用这个目标。场景选择目标后，只会提供与之匹配的身份和绑定。

## 目标保存与发布快照 {#snapshot}

保存目标只是维护公开配置。场景发布与运行会固定所用上下文，后续修改配置不能被理解为悄悄改写旧运行。要切换服务或环境，应明确创建/选择正确目标、重新核对场景版本和执行计划。

## 目标系统 {#target}

目标是本次被测服务的完整公开配置，包含基础地址、环境和认证策略。它决定请求去哪里及采用哪种登录方式。

**在哪里使用：** 环境管理 → 目标系统；用例管理 → 场景设置 → 目标系统。

**填写或阅读示例：** 配置一个“测试客户服务”，选择 `env-test` 并填真实测试 API 根地址。

**应该看到什么：** 场景可选到该目标，计划显示一致的目标和环境。

**常见错误：** 把服务显示名称当目标 ID，或试图通过步骤 URL 指向未配置的任意外部系统。

## 配置类型 {#profile-kind}

目标、身份和绑定是三类不同资源。目标管服务，身份管谁来测试，绑定管在哪个业务空间执行。

**在哪里使用：** 环境管理顶部 → 环境、目标系统、身份、租户 / 项目绑定标签页。

**填写或阅读示例：** 依次选择“目标系统”保存 A，再“身份”保存 B，最后“租户/项目绑定”保存 C。

**应该看到什么：** 后创建的资源可以从已有目录选择前置资源，不需要手抄整份 JSON。

**常见错误：** 还没有目标就配置身份，或把账号密码写进目标公开 JSON。

## 要求项目上下文 {#requires-context}

系统区分租户/项目时开启，要求运行固定到匹配绑定并验证服务回读的归属。

**在哪里使用：** 目标系统 → 要求项目上下文。

**填写或阅读示例：** 客户服务按项目隔离，勾选此项，随后配置绑定和归属查询。

**应该看到什么：** 依赖项目上下文的运行只有在归属已得到要求的证据时才继续。

**常见错误：** 为了消除预检报错关闭真实必需的上下文，或以请求头注入成功代替归属回读。
