# 隔离与解除：保留不稳定历史

隔离记录说明为什么暂不采纳某旅程，解除也不自动产生成功证据。

## 标记与处理 {#flow}

旅程列表填写隔离原因和带时区到期时间 → 标记隔离 → 修复并验证 → 在解除区域填写真实隔离ID和依据 → 追加解除记录。原始原因、到期与历史都保留，不覆盖。

隔离到期只是期限过去，不证明问题修好；解除后仍要满足同环境/构建、当前版本、新鲜live成功、有效断言和清理等证据条件。

## 隔离标记 {#quarantine}

记录不稳定或缺验证的原因，覆盖判定仍保留未验证。

**在哪里使用：** 旅程列表 → 隔离原因/到期 → 标记隔离。

**填写或阅读示例：** 原因“设备构建不匹配待补”，到期填 `2026-11-01T09:00:00+08:00`。

**应该看到什么：** 生成可追溯隔离记录，不删除旧run。

**常见错误：** 设到期就以为届时自动变已验证。

## 解除隔离记录 {#resolve-quarantine}

追加解除记录，明确处理了哪条隔离及依据。

**在哪里使用：** 旅程面板 → 隔离记录ID和修复/验证依据。

**填写或阅读示例：** 填实际隔离ID，描述构建修正和对应验证run。

**应该看到什么：** 历史保留，处理状态更新。

**常见错误：** 随便写“已修复”，或把解除当成功运行。
