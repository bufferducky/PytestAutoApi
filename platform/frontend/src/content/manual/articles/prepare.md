# 开始前准备哪些资料

先把真正依赖的资料准备齐，避免在页面里试填大量未知值。

## 准备清单与分工 {#checklist}

| 资料 | 示例（均为占位） | 通常由谁提供 |
| --- | --- | --- |
| 被测环境和系统地址 | 测试环境、https://api.example.test | 项目研发/运维 |
| 接口契约 | GET /api/customers；page 为整数 | 接口负责人/已有接口文档 |
| 成功响应 | code=200，data.records 是数组 | 接口负责人及实际响应证据 |
| 测试账号 | 对应身份秘密引用 | 账号管理员/服务运行人员 |
| 租户与项目 ID | tenant-test、project-test | 业务负责人/测试资源清单 |
| 被测构建 | 业务服务提交号或镜像版本 | 发布人员 |

上表域名使用保留的示例后缀 `.test`，本手册没有为你部署这个业务服务。执行前必须换成已有且已确认的测试接口；字段和响应也要按真实契约调整。

## 网页能配什么，服务端要准备什么 {#responsibility}

网页可以保存公开地址、登录字段、令牌解析路径、秘密引用名称、身份与项目绑定。真实账号密码保存在运行 API/worker 的服务环境，网页不负责生成这些值。

例如网页填写 `env:PYTA_SECRET_TEST_PASSWORD`，意思是“运行时去服务端找这个名字对应的密码”。它不等于密码本身，也不会自动创建环境变量。遇到“秘密不存在”，把**引用名称**交给服务运行人员核对，不把密码粘进公开参数。

业务数据库核验还需要服务端注册数据源；普通 HTTP 查询不要求你先配置数据库。详情见[业务数据源](/manual/business-datasource#business-datasource)。

## 不知道某项值怎么办 {#unknown-values}

不知道路径、字段或业务码时先查接口契约，不靠勾选“已确认”尝试绕过。保存配置、预检配置、真正登录、实际测试是不同动作；可用性要看各项结果，不能只看目录里“可用”的标签。
