# 套件：组合固定版本场景

> 当前界面入口：套件页左侧搜索并选择套件，“套件设置”填写名称，“场景编排”选择固定场景版本并调整顺序，“发布与版本”和“正式运行”分别完成发布和执行。草稿编辑不会改变已发布版本。

套件把一批已发布场景组合为同一次回归，固定顺序和预算。

## 创建与更新 {#create}

套件管理新增 → 命名“客户查询回归” → 添加场景 → 选择真实目录中的场景和发布版本 → 保存预检 → 发布套件版本。场景修复发布v2后，套件仍引用v1，必须显式更新引用并发布新套件。

## 套件参数格式 {#parameters}

```json
{"scenario-customer":{"page":2},"scenario-other":{"limit":10}}
```

外层为真实场景资产ID，不是显示名称；内层才是各场景schema允许的参数。单场景运行直接填 `{"page":2}`，不要多包这一层。

## 场景引用 {#scenario-ref}

由场景资产ID和已发布version组成，可按计划顺序组合。

**在哪里使用：** 套件 → 组合场景。

**填写或阅读示例：** `{"scenario_id":"真实场景ID","version":1}`，优先在目录下拉选择。

**应该看到什么：** 编辑场景草稿不改套件v1引用。

**常见错误：** 填显示名称或不存在版本，保存后不核对回填值。

## 执行总预算 {#budget}

整套主流程允许时间，与排队预算、HTTP超时和等待预算分别约束。

**在哪里使用：** 套件/调度 → 执行预算秒。

**填写或阅读示例：** 确认查询预计30秒，可按合理上限设300秒。

**应该看到什么：** 预算耗尽结束主流程并尝试独立清理。

**常见错误：** 以为每个请求都各有整套预算，或与耗时卡片混淆。
