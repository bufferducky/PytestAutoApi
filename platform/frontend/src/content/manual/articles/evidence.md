# 附件与证据保留

证据用于复盘，不因添加一份附件就自动证明业务通过。

## 追加附件 {#attach}

运行详情展开附件，填写脱敏JSON，可指定真实步骤ID。先确认不含凭证和原始客户数据。保存后看附件索引、可用性和关联步骤；附件可回收或不可用时，结论需要保留缺口。

## 保留策略的顺序 {#policy}

默认详细元数据90天、普通附件14天、失败附件30天。保存策略只影响后续保留判断，不立即删除；只读预览 → 核对范围 → 确认回收。活跃运行和标记保留的证据不参与普通到期回收。

## 脱敏 JSON 附件 {#attachment}

补充可审查的公开证据，不替代真实断言。

**在哪里使用：** 运行详情 → 脱敏JSON附件。

**填写或阅读示例：** `{"issue":"详情ID不一致","expected_id":"customer-001","actual_id":"customer-002"}`，均用合成/已核验脱敏内容。

**应该看到什么：** 索引显示新附件与类型大小。

**常见错误：** 上传真实Token、密码或客户原始内容。

## 附件关联步骤 {#attachment-step}

将附件归到当前run已有步骤，留空为运行级。

**在哪里使用：** 附件表单 → 关联步骤ID。

**填写或阅读示例：** 填本run的get_customer步骤ID，先核对实际索引。

**应该看到什么：** 附件关联目标步骤，没有创建新步骤。

**常见错误：** 填别的run的ID或以为重命名步骤。

## 标记保留 {#pin}

保护附件不被普通到期回收，不改变内容与结果。

**在哪里使用：** 附件列表 → 标记保留。

**填写或阅读示例：** 关键故障证据在回收前标记保留。

**应该看到什么：** pinned状态改变，取消后再按策略。

**常见错误：** 以为能修复已损坏或已回收文件。

## 证据保留天数 {#retention-days}

分别维护元数据、普通附件、失败附件的保留时长。

**在哪里使用：** 证据保留 → 三类天数。

**填写或阅读示例：** 按团队需要设90/14/30，允许范围1—3650天。

**应该看到什么：** 保存未来策略，需另行预览回收。

**常见错误：** 把保存当立即删除，或全设1却未核对故障证据。

## 证据保留与回收 {#retention}

列出到期和保留范围，尚不删除。

**在哪里使用：** 证据保留 → 只读预览。

**填写或阅读示例：** 先看ready/preserved及metadata_ready。

**应该看到什么：** 可核对哪些记录仍被保护。

**常见错误：** 把预览结果当已回收。

## 回收到期证据 {#reclaim}

实际处理刚预览范围，会影响后续证据查看。

**在哪里使用：** 证据保留 → 确认并回收。

**填写或阅读示例：** 核对后确认“保留其他证据”，再回收。

**应该看到什么：** 返回处理结果，运行结论不因此变通过。

**常见错误：** 未看范围就批量删除关键历史。
