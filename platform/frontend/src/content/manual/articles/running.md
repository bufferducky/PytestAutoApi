# 计划预览与真实运行

> 当前界面入口：在用例或套件工作区选择“正式运行”，选择固定版本、环境、被测构建和参数，先预览计划再核对范围提交。执行结果页面左侧筛选并选记录，右侧查看概览、步骤证据或资源；关键词查找只过滤当前页。

先确认本次会测谁、用哪版、做什么，再实际执行。

## 从预览到结果 {#flow}

```mermaid
flowchart LR
  A[选择版本和参数] --> B[只读计划预览]
  B --> C[核对身份项目和副作用]
  C --> D[确认真实运行]
  D --> E[后台执行器领取]
  E --> F[请求断言及清理]
  F --> G[查看终态证据]
```

预览不创建业务数据。正式运行会真实请求，若场景含write就可能修改数据。返回run ID只是受理，queued/running都未通过，需等待终态。

## 运行环境 {#run-environment}

按目标所属环境确定；显式指定也必须一致。

**在哪里使用：** 运行/调试 → 环境。

**填写或阅读示例：** 目标env-test，选择同一环境并预览核对。

**应该看到什么：** 快照记录相同环境及真实地址。

**常见错误：** 改显示环境名称就期待目标换域名。

## 被测构建 {#build}

被测业务提交或镜像/App版本，不是测试资产版本。

**在哪里使用：** 运行/旅程/报告 → 构建。

**填写或阅读示例：** 填真实SHA或镜像标识；未知可用于调试但保留证据缺口。

**应该看到什么：** 结果可关联实际业务版本。

**常见错误：** 填场景v1或捏造版本满足门槛。

## 计划预览 {#plan}

解析固定场景、步骤、资源策略和影响范围，不发业务请求。

**在哪里使用：** 已发布资产 → 计划预览。

**填写或阅读示例：** 选v1与参数，查看target/environment/side effects。

**应该看到什么：** 可审查将执行的范围，但未证明服务可用。

**常见错误：** 没看write范围就确认，或以为预览已创建资源。

## 提交真实运行 {#run}

登记任务交执行器处理，实际请求后保存结果。

**在哪里使用：** 已发布资产 → 提交真实运行。

**填写或阅读示例：** 预览确认后提交，记录run ID到结果页追踪。

**应该看到什么：** queued/running之后得到终态。

**常见错误：** 重复点击造多次运行，或以为受理就是通过。

## 运行范围确认 {#live-confirmation}

人工确认身份、项目、数据和可能写入符合本次意图。

**在哪里使用：** 运行 → 范围确认。

**填写或阅读示例：** 看计划后勾选；范围不符先改。

**应该看到什么：** 确认后才允许提交真实请求。

**常见错误：** 把勾选当作权限已验证或业务已成功。

## 执行模式 {#transport}

live是真请求，mock为模拟历史，historical_unknown为旧记录缺标记。

**在哪里使用：** 执行结果/计划 → 模式。

**填写或阅读示例：** 按同环境live筛选比较；模拟历史单独识别。

**应该看到什么：** 不把历史模拟当真实发布证据。

**常见错误：** 看到live即认为全部业务和设备都通过。
