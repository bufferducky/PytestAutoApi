# 测试身份与秘密引用

身份说明“以谁的账号测试”，网页保存的是秘密名称，而不是密码。

## 创建身份 {#create}

先保存目标。在环境管理顶部选择“身份”标签页 → 新增配置 → 选择允许使用的目标 → 填写两个秘密引用 → 保存。再由服务运行人员确认 API 和 worker 都能读取对应秘密。

```text
账号引用：env:PYTA_SECRET_TEST_USER
密码引用：env:PYTA_SECRET_TEST_PASSWORD
```

上面是引用名称示例，复制名称不会自动得到账号。实际值应由运行服务提供，不放进 URL、公开参数、日志附件或浏览器存储。

## 为什么列表里没有这个身份 {#not-listed}

先看身份“支持的目标系统”是否包含当前场景目标；再看目标和环境是否匹配。添加本地配置关联不会给业务账号新增权限，仍需服务端真实权限证据。

## 测试身份 {#identity}

选择本次要使用的测试账号配置。与目标绑定后由平台解析秘密并按目标协议登录。

**在哪里使用：** 环境管理 → 身份；场景设置 → 身份。

**填写或阅读示例：** 使用专门的测试账号身份 `identity-customer-test`；匿名接口才可按契约不选身份。

**应该看到什么：** 已保存身份会出现在匹配目标的选择列表，运行记录关联该身份。

**常见错误：** 选了名称相似但业务角色不同的账号，或以为身份保存即已验证登录。

## 支持的目标系统 {#target-ids}

限制该身份在平台里可用于哪些目标，避免同一账号误配到另一服务。

**在哪里使用：** 身份 → 支持的目标系统。

**填写或阅读示例：** 多选确实支持此账号的“测试客户服务”等目标。

**应该看到什么：** 场景只提供与当前目标匹配的身份。

**常见错误：** 把它当作业务系统的授权管理；它不会授予账号任何服务器权限。

## 秘密引用 {#secret-ref}

秘密引用是一张取值凭条。env: 表示运行服务的环境变量，允许使用 PYTA_SECRET_ 命名空间。

**在哪里使用：** 身份 → 账号引用/密码引用。

**填写或阅读示例：** 分别填 `env:PYTA_SECRET_TEST_USER` 和 `env:PYTA_SECRET_TEST_PASSWORD`，由运行人员注入实际值。

**应该看到什么：** 配置检查确认引用可解析；真正登录由执行登录预检或运行验证。

**常见错误：** 直接填密码，或只在自己终端设置变量却没有让 API/worker 进程加载。
