# 跟着做：第一条接口查询

用一条已确认的只读查询，学会配置、调试、发布和查看结果。

## 本例约定 {#contract}

这是可替换的教学契约，不是平台内置接口。请让接口负责人提供你实际环境中同样性质的接口，再按真实字段替换。

```text
方法：GET
接口：/api/customers
查询参数：page=1
预期响应：{"code":200,"data":{"records":[{"id":"customer-001","name":"测试客户"}]}}
```

这里假设接口无须登录、无项目上下文，只读且已确认。你的接口需要登录时，应先完成[身份配置](/manual/identity#identity)，不要把认证关掉去套用本例。

## 逐项填写 {#steps}

1. **环境管理**中创建/选择测试环境，填写已知基础地址并保存。
2. 展开“目标系统、身份与项目绑定”，类型选目标系统，新增目标，选择该环境、核对目标基础地址。按接口实际要求设置认证，本例为无认证、无需项目上下文。
3. 进入**用例管理**，新增业务场景。名称填“客户列表查询”，优先级 P1，目标选择刚才的目标，身份和绑定在本例可留空。
4. 添加 HTTP 步骤：稳定 ID `list_customers`，名称“查询客户列表”，阶段 `verify`，方法 GET，URL `{{host}}/api/customers`，业务用途选择 `query`。
5. 展开请求选项，查询参数新增名称 `page`、值 `1`；请求体类型选“无”。按已取得的真实契约确认请求。
6. 添加两条断言，填写下表。第二条是本教学响应才有的字段，实际响应不同需要改字段路径。

| 断言名称 | 来源 | 字段路径 | 比较规则 | 期望 JSON |
| --- | --- | --- | --- | --- |
| 业务码正确 | 响应体 | code | equals | 200 |
| 客户列表存在 | 响应体 | data.records | exists | null（此规则只检查存在） |

## 调试并读懂反馈 {#debug}

点击“调试当前整场景”，公开参数保持 `{}`，核对实际目标与范围，再点击“确认范围并真实调试”。**调试会真实请求接口**，不自动保存草稿或发布。

应该看到运行 ID、终态与每条断言的预期/实际值。code 实际为字符串 `"200"` 而期望为数字 `200` 时，不要不看契约就改成通过；先确认真实类型。看[JSON 类型](/manual/json#types)和[断言](/manual/assertions#expected)。

## 保存、发布、正式运行 {#formal-run}

1. 调试符合预期后保存草稿，确认没有“未保存”提示。
2. 点击发布预检，处理返回的具体路径错误；预检本身不发业务请求。
3. 填写发布说明，例如“客户列表基础查询与业务码断言”，发布不可变版本。
4. 选择已发布版本，预览计划，核对环境、构建和参数，再确认真实运行。
5. 到执行结果查看最终状态、步骤与断言。受理成功还需要等待执行器完成。
6. 要重复批量执行，按[套件教程](/manual/suites#scenario-ref)引用这个固定版本，再配置[调度](/manual/scheduling#schedule-save)。

## 常见卡点 {#problems}

- 目标目录为空：先保存目标，确认目标属于所选环境。
- 请求返回 401：真实接口需要登录，先补身份和协议，不反复点运行。
- URL 未定义变量：检查 `host` 来自目标，别写成 `{{baseUrl}}`。
- 预检按钮禁用：先保存当前编辑，确认已选择资产。
- 发布后运行仍是旧内容：确认选择了新版本，套件也要显式更新版本。
