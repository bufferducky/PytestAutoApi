# 桌面布局与验收

## 范围

2026-10-27 用户明确后续不再考虑手机页面兼容。当前与后续页面以桌面浏览器为目标，验收宽度为 1280、1440、1920px。手机、触屏及手机“桌面站点”的适配和回归不作为要求。历史 CSS 可以保留，但不为本次需求额外建设移动布局。

## 可执行约束

- 页面主容器与 Grid/Flex 子项使用可收缩轨道及 `min-width: 0`。
- 标题与长元信息并排时允许换行，不能让元信息把中文标题挤到逐字换行。
- 桌面侧栏使用 `auto auto 1fr` 行分配，品牌和导航按内容保持高度，footer 靠下。
- 六个业务导航和新增“使用手册”共七个主入口可达，扩展工具保留独立入口。
- 表单、select、fieldset 和标签可收缩；长 ID/说明可换行。
- 宽表格、原始证据、代码和大流程图在自身区域滚动或展开；不能用全页 `overflow-x:hidden` 掩盖被裁切内容。
- 手册采用可读的多级目录、正文与小节定位区，不能为了塞满多列把正文挤到不可读。
- 鼠标与键盘均可操作，焦点可见，交互链接不能因按钮失焦立即被关闭。

## 真实浏览器回归

复用 `tests/frontend/responsive-layout.mjs` 的 `widths`、`routes`、`measureLayout` 和 `assertLayout`；桌面视口检查六个主业务路由、扩展工具及使用手册：

1. `documentElement.scrollWidth <= clientWidth + 1`，宽内容在局部查看。
2. 七个主导航链接存在；品牌高度 < 100px，导航行高度 < 120px。
3. 存在 hero 标题时宽度至少为 `min(240px, 内容区宽度 - 80px)`，高度 < 250px。
4. 使用非空资产与运行，检查默认与展开高级配置后的可读性；不能清空数据规避长内容。
5. 手册需检查长文章、代码/字段表、实际 Mermaid 图和打开的问号，不能仅看首页空壳。
6. 1280/1440/1920px 均验收，保留代表性桌面截图；不再执行手机及触屏专项。

`tests/backend/test_platform_frontend_browser.py` 使用生产构建及隔离本地 API，原有创建/保存/预检/发布/运行/诊断断言继续保留。手册关联还需验证新标签页精确定位和原页未保存内容保持。

## 历史资料

2026-10-25/26 的手机布局修复及九宽度验收记录保留在 `docs/bug-analysis-mobile-layout.md` 与历史 reviews 中，用于追溯旧版本，不构成当前新增需求。可收缩布局、非空数据验证和局部滚动规则继续适用于桌面。
