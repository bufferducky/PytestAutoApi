# 前端全量体验重构与 UI 组件库接入

## 目标与用户价值

将配置表单式界面改为日常可持续使用的桌面接口测试工作台，同时解决页面观感、功能查找、操作路径、接口编写和调试体验。用户要求全部记录、通过 Goal 持续完成全部优化，且必须实际使用 UI 组件库。不能以换按钮样式、只完成用例页或构建成功作为完成标准。

## 背景与范围依据

当前采用 Vue 3、TypeScript、Vite、Pinia 和 Vue Router，无 UI 组件库。编辑、调试、发布和运行仍集中在长页面，其他页面存在入口隐藏、重复目录、列表与详情距离过远等问题。问题、严重性、代码定位和验收映射仅维护在 [问题清单](./ux-audit.md)。

本任务承接用户新提出的全量体验重构，不改写 `10-26-frontend-workbench-refresh` 的历史结论。当前工作区已有大量未提交业务和手册改动，以当前文件为起点增量实施。

## 页面方案与关键决定

- 组件库采用 Element Plus，保留 Vue 技术栈。依赖版本在接入时依据实际环境安装、锁定并验证，不在规划中编造已验证版本。
- 用例页左侧为可搜索场景和当前场景步骤，中间编辑当前步骤；参数、请求头、请求体、断言、提取和高级设置由具名标签页到达，下方为调试结果。1280px 上下分区，宽屏可增加并排空间，不强塞窄表单。
- 场景设置、发布版本和正式运行通过明显顶层标签进入；保存和调试始终就近可达，切步骤不要求先保存整场景。
- 套件、环境、调度以目录选择和当前对象编辑为主线；环境/目标/身份/绑定使用明确标签；运行列表与详情就近展示，常用筛选常显。
- 六个业务入口、手册和扩展工具保持可达，现有 assetId、runId、手册文章和小节深链接继续有效。
- 保留浅色中性工作台方向，统一蓝色主操作、文字层级、间距和紧凑控件。本次覆盖全部页面，不新增主题切换产品功能。
- 业务确认采用组件库对话框展示范围；浏览器刷新/关闭提示仍遵循 beforeunload 机制。

## 范围外

不改后端接口、数据库、鉴权协议、执行引擎及发布证据许可规则；不自动触发公司业务请求、启用公司调度或部署远端；不新增移动端专项、团队权限、云同步。JSON、历史标识、导入迁移和高级能力保留，只改变入口和表达。

## 风险与验证约束

- 旧浏览器测试依赖原生 select、summary 和 window.confirm，必须适配真实库操作并保留业务断言，不能删回归换取通过。
- 全局表单 CSS 可能干扰库内部控件，要收窄作用域并验证下拉、弹层与帮助。详见 [设计](./design.md)。
- 现有检查基线及后续命令记录在 [实施计划](./implement.md)；历史截图仅作设计参考，不代表当前运行页面。
