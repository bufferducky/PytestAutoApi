# 测试平台的证据与交付契约

适用：修改预检判定、场景编译、运行创建、覆盖/发布报告、配置编辑或镜像文件交付时读取。

来源：[2026-10-25 系统审查](../../../docs/reviews/2026-10-25-framework-audit/README.md)。2026-10-26 已修复 F02/F03 的预检/运行范围路径，并对 F09 无消费者声明显式拒绝。新增调用链回归与接入行为见 [API/Web 契约](../backend/apiweb-workbench-contracts.md)；其余历史审查项按当前证据分别核实。

## 运行范围

- 为每条运行记录传输方式、验证对象、environment、target、identity/binding、构建、资产版本与时间。`live` 只表示发出了真实请求；平台自检与言迹业务回归分别展示。
- 资产入口从固定 target 快照派生单一 environment，并与显式输入校验。混合环境采用明确模型或拒绝；UI 缺字段不能导致有环境的目标产生无环境运行。
- 调试运行允许明确标记构建未知；可用于发布的证据必须关联实际构建。单 run 的执行证据完整性与业务发布许可分别命名、分别判定。
- 验证默认浏览器提交路径，然后按 environment/target/build 查询结果；不要只测手工填全字段的服务调用。

## 预检语义

- configuration 表示配置可解析；authentication 表示登录被验证；service 表示查询可用；context 表示所需 tenant/project 的归属已被回读校验。
- `code=200`、checks 非空、已注入 Dept-Id/Tenant-Id 都不能单独证明归属。必需归属无证据时返回 not_verified 或拒绝依赖该归属的操作；无需上下文时返回 not_required。
- 必须保留三个反例：仅 code 查询不能获得 context passed；错误 tenant/project 必须失败；正确归属才通过。框架反例不能被描述成业务服务端越权。

## 编译与编辑

- 每个可接受的声明字段都必须有编译/执行消费者或明确的拒绝原因。尤其检查 plugin_refs、请求模式、headers/query、等待策略和 fixture 引用。
- 编译差分检查字段是否丢失；行为检查声明是否产生预期效果。插件引用字符串合法不等于插件已执行。
- UI 显示未保存状态、服务端 revision 与发布版本。预检/发布必须清楚指向已保存内容；新增场景重置上一条的运行参数和上下文状态。

## 发布产物

- 为每个运行时文件依赖标注来源：镜像内受控 bundle、明确挂载或上传资产。检查 docs/data/Files 等源码目录的文件是否真的随产物交付。
- 在干净镜像中验收导入、媒体访问和缺失提示；完整源码树上的通过不替代部署验收。研究 bundle 只包含经过审查的数据，不整包复制凭证或客户资料。
- 检查规范和受控研究输入是否被 Git 跟踪；全局忽略可能使本机存在的资料在 checkout/CI 中消失。仅选择性纳入脱敏资料，秘密与运行状态继续隔离。
- env:PYTA_SECRET_* 引用必须有服务端注入和轮换路径。配置引用成功与秘密可用分别验证，公开响应只返回可用性。

## 验收范围

- 分别记录：离线机制、隔离 MySQL、浏览器关键路径、干净镜像、公司业务 live、设备、模型质量。每层写明命令、结果和未运行原因。
- 根默认测试入口必须清楚区分离线检查与会发业务请求的旧用例。可选检查跳过时保留范围缺口，不能只报通过数。
- 业务回归暂缓时保留未验证事实；后续机制完成不自动解除该缺口。先恢复一个可独立重复的业务闭环，再扩展平台能力。

## 修复检查清单

- [ ] 从 UI 默认路径创建运行，environment/build 在快照、存储、查询和报告中一致。
- [ ] 归属缺失、错误归属、正确归属三种输入得到不同且诚实的结果。
- [ ] 已接受声明从编译到执行均生效，不支持字段明确拒绝。
- [ ] 干净部署的资源文件/秘密引用有可验收的交付来源。
- [ ] 结果范围能区分平台自检、业务查询、写入、UI/设备与质量评测。
